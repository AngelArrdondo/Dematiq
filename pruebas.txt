────────────────────────────────────────────────────────────────────────────────
1.1  PÁGINA DE INICIO — index.html
────────────────────────────────────────────────────────────────────────────────
Archivo: /index.html

La página de inicio es un archivo HTML estático que carga todo su contenido
dinámico desde la API pública mediante fetch(). No requiere renderizado en
servidor. Estructura de secciones:

  HERO CAROUSEL (Sección Superior)
  - Carrusel Bootstrap 5 con diapositivas generadas dinámicamente.
  - Datos obtenidos con: fetch('/api/contenido.php?clave=home')
  - Cada slide tiene: título (h1), subtítulo (p) e imagen de fondo.
  - Las diapositivas se construyen en JavaScript insertando HTML al carrusel.
  - Si la API falla, se muestra un slide de respaldo con imagen fija.

  EMPRESAS / MARCAS ASOCIADAS (Marquee Animado)
  - Banda horizontal con logos de partners que desfilan en loop (CSS animation).
  - Datos obtenidos con: fetch('/api/contenido.php?clave=partners')
  - Cada partner tiene: nombre, logo (ruta de imagen) y url (enlace externo).
  - Se duplican los logos automáticamente para lograr el efecto de marquee continuo.

  SOLUCIONES Y SERVICIOS (Grid de Tarjetas)
  - Datos obtenidos con: fetch('/api/contenido.php?clave=servicios')
  - Cada tarjeta muestra: nombre del servicio e imagen representativa.
  - Grid responsivo Bootstrap: 2 columnas en móvil, 4 en escritorio.
  - Cada tarjeta enlaza a su página dedicada (p. ej. /pages/ensamble.html).

  PROYECTOS DESTACADOS (Carrusel de Proyectos)
  - Datos obtenidos con: fetch('/api/contenido.php?clave=proyectos')
  - Cada proyecto: nombre, descripción breve, imagen y href (enlace).
  - Carrusel Bootstrap con controles de navegación anterior/siguiente.

  CONTADOR DE VISITAS
  - Invisible para usuarios normales; visible solo con URL ?admin en la query.
  - Almacena conteos en localStorage ('dematiq_visits' y 'dematiq_visits_daily').
  - Registra la última fecha de visita para resetear el contador diario.
  - Envía la visita a counterapi.dev para conteo externo/backup.
  - Historial semanal guardado en localStorage ('dematiq_visits_weekly').

  ACTUALIZACIÓN EN VIVO (BroadcastChannel)
  - Escucha en el canal 'dematiq-live' vía BroadcastChannel API del navegador.
  - Cuando el admin guarda contenido, emite un evento en ese canal.
  - La página principal recarga su contenido dinámico sin hacer full reload.
  - Permite que múltiples pestañas abiertas se actualicen simultáneamente.


────────────────────────────────────────────────────────────────────────────────
1.2  API PÚBLICA DE CONTENIDO — api/contenido.php
────────────────────────────────────────────────────────────────────────────────
Archivo: /api/contenido.php

Endpoint REST de solo lectura accesible sin autenticación.

  Método soportado: GET
  Header: Cache-Control: public, max-age=60 (cache de 60 segundos)
  Parámetro: ?clave=NOMBRE_CLAVE

  Si se proporciona 'clave' → devuelve el valor JSON de esa clave específica.
  Si no se proporciona 'clave' → devuelve todas las claves y sus valores.

  Respuesta: JSON con estructura { ok: true, data: <valor> }
  Fuente de datos: tabla 'contenido' en MariaDB, valores almacenados como JSON.

  Claves disponibles en producción:
    - home        → datos del hero carousel (array de slides)
    - partners    → logos de marcas asociadas (array de objetos)
    - servicios   → tarjetas de servicios (array de objetos)
    - proyectos   → proyectos destacados (array de objetos)
    - industrias  → sectores industriales (array de objetos)
    - contacto    → email, whatsapp, horario, dirección, redes sociales
    - nosotros    → contenido de la página "Sobre Nosotros"
    - ensamble, maqcontrol, maqprob, maqinspe, maclim,
      maqmar, macrobot, maqindus → páginas de soluciones/máquinas

1.3  PÁGINA DE LOGIN — pages/corporativo/login.php
────────────────────────────────────────────────────────────────────────────────
Archivo: /pages/corporativo/login.php

Punto de entrada al panel de administración. PHP con procesamiento POST en el
mismo archivo.

  DISEÑO VISUAL
  - Layout de dos paneles: izquierdo con branding animado, derecho con formulario.
  - Panel izquierdo: canvas con red de nodos (partículas conectadas animadas),
    logo de Dematiq y eslogan corporativo.
  - Panel derecho: formulario oscuro con reloj en tiempo real (setInterval 1s).
  - Fondo general: partículas canvas animadas (efecto de profundidad).

  FORMULARIO DE LOGIN
  - Campos: username (text) + password (password).
  - Checkbox "Recordar sesión": guarda el username en cookie por 30 días.
    Si la cookie existe al cargar la página, prellenará el campo de usuario.
  - Enlace "¿Olvidaste tu contraseña?" → forgot-password.php.

  FLUJO DE AUTENTICACIÓN
  - POST al mismo archivo, llama Auth::login($_POST['username'], $_POST['password']).
  - Si Auth::login() devuelve true → redirect 302 a /admin/dashboard.php.
  - Si devuelve error → se muestra el mensaje de error inline debajo del formulario.
  - Todos los errores se sanitizan con htmlspecialchars() antes de mostrar.

  GESTIÓN DE SESIÓN POST-LOGIN
  - Auth::login() establece cookie 'dematiq_session' (httponly, SameSite=Strict,
    Secure si es HTTPS) con el token de sesión.
  - La sesión se vincula al User-Agent del navegador para evitar hijacking.

2.1  SISTEMA DE AUTENTICACIÓN — includes/auth.php
────────────────────────────────────────────────────────────────────────────────
Archivo: /includes/auth.php

Clase estática 'Auth' con toda la lógica de seguridad del sistema.

  CONSTANTES DE SEGURIDAD
    MAX_INTENTOS     = 5    (intentos fallidos antes de bloqueo por usuario)
    BLOQUEO_MINUTOS  = 15   (duración del bloqueo por usuario)
    SESSION_HORAS    = 8    (duración de la sesión activa)
    IP_MAX_FALLOS    = 20   (fallos por IP antes de bloqueo temporal por IP)

  MÉTODO login($username, $password)
  1. Rate limiting por IP: cuenta fallos de esa IP en los últimos 15 minutos
     en log_accesos. Si supera IP_MAX_FALLOS → bloquea con 'bloqueado' en log.
  2. Busca usuario en DB: SELECT WHERE username = ? (case sensitive).
  3. Si usuario no existe → registra fallo en log_accesos, incrementa intentos.
  4. Si usuario está inactivo (activo=0) → rechaza, registra log.
  5. Verifica bloqueo temporal: si intentos_fallidos >= MAX_INTENTOS y
     ultimo_fallo fue hace menos de BLOQUEO_MINUTOS → acceso denegado.
  6. password_verify($password, $usuario['password_hash']) con bcrypt.
  7. Si contraseña incorrecta → incrementa intentos_fallidos, registra log.
  8. Si contraseña correcta:
     a. Resetea intentos_fallidos = 0.
     b. Genera token = bin2hex(random_bytes(32)).
     c. INSERT en tabla 'sesiones': user_id, token, user_agent, ip, expires_at.
     d. setcookie('dematiq_session', token, [...]) con opciones de seguridad.
     e. Registra log con resultado='exitoso'.
     f. Retorna true.

  MÉTODO check(): array|false
  - Lee cookie 'dematiq_session'.
  - SELECT sesion + usuario JOIN WHERE token = ? AND activo = 1 AND
    expires_at > NOW() AND user_agent = $_SERVER['HTTP_USER_AGENT'].
  - Si coincide → retorna array con datos del usuario.
  - Si no coincide → retorna false (sesión inválida, expirada o hijacked).

  MÉTODO require(): array (o redirect)
  - Llama a check(). Si false → redirect a /pages/corporativo/login.php.
  - Si el perfil no está completo → redirect a /admin/complete-profile.php.
  - Retorna el array del usuario si todo es válido.

  MÉTODO isProfileComplete($user): bool
  - Verifica que primer_nombre, apellido_paterno, apellido_materno,
    email_contacto y telefono no sean nulos/vacíos.

  MÉTODO logout()
  - DELETE FROM sesiones WHERE token = ? (solo la sesión actual).
  - Elimina la cookie 'dematiq_session' (setcookie con expires en pasado).

  MÉTODO invalidarOtrasSesiones($userId)
  - DELETE FROM sesiones WHERE user_id = ? AND token != current_token.
  - Se usa al cambiar contraseña para cerrar sesiones en otros dispositivos.

  MÉTODO csrfToken(): string
  - Lee cookie 'dematiq_csrf'. Si no existe → genera bin2hex(random_bytes(32)).
  - Guarda el token en cookie 'dematiq_csrf' (no httponly, para que JS lo lea).
  - SameSite=Strict. Retorna el token.

  MÉTODO csrfVerify(): bool
  - Compara X-CSRF-Token del header (peticiones AJAX) o _csrf del POST body
    contra la cookie 'dematiq_csrf' usando hash_equals() (timing-safe).

  MÉTODO registrarLog($userId, $username, $resultado, $ip, $userAgent)
  - INSERT en tabla 'log_accesos' con todos los campos de auditoría.
  - resultado puede ser: 'exitoso', 'fallido', 'bloqueado', 'inactivo'.

2.2  CONEXIÓN A BASE DE DATOS — includes/conexion.php
────────────────────────────────────────────────────────────────────────────────
Archivo: /includes/conexion.php

Crea la variable global $pdo (PDO).

  Parámetros de conexión (en orden de prioridad):
    1. Variables de entorno: DB_HOST, DB_NAME, DB_USER, DB_PASS
    2. Valores hardcoded de fallback: 127.0.0.1, dematiq_db, dematiq_app

  Opciones PDO configuradas:
    - PDO::ATTR_ERRMODE → PDO::ERRMODE_EXCEPTION
    - PDO::ATTR_DEFAULT_FETCH_MODE → PDO::FETCH_ASSOC
    - PDO::ATTR_EMULATE_PREPARES → false (prepared statements reales)
    - charset=utf8mb4 en el DSN

  No hace pooling ni singleton — cada request PHP abre su propia conexión.


────────────────────────────────────────────────────────────────────────────────
2.3  SISTEMA DE CONTENIDO — includes/contenido.php
────────────────────────────────────────────────────────────────────────────────
Archivo: /includes/contenido.php

Clase estática 'Contenido' — abstracción sobre la tabla 'contenido' en MySQL.
Implementa un almacén clave-valor donde el valor es JSON arbitrario.

  Estructura de tabla 'contenido':
    clave  VARCHAR(100)  PRIMARY KEY
    valor  LONGTEXT      (JSON serializado)

  MÉTODO get(string $clave): mixed
  - SELECT valor FROM contenido WHERE clave = ?
  - Deserializa con json_decode($valor, true).
  - Si la clave no existe → retorna null.

  MÉTODO set(string $clave, mixed $valor): void
  - Serializa $valor con json_encode().
  - INSERT INTO contenido (clave, valor) VALUES (?, ?)
    ON DUPLICATE KEY UPDATE valor = VALUES(valor)
  - Patrón upsert: crea si no existe, actualiza si ya existe.

  MÉTODO getAll(): array
  - SELECT clave, valor FROM contenido
  - Retorna array asociativo [clave → valor_deserializado].

3.3  MÓDULO ACCESOS / AUDITORÍA — admin/pages/accesos.php
────────────────────────────────────────────────────────────────────────────────
Archivo: /admin/pages/accesos.php

Panel de auditoría de intentos de login al sistema.

  CARGA DE DATOS
  - PHP carga directamente los últimos 200 registros de log_accesos al renderizar.
  - No usa AJAX; los datos están embebidos en la página como array PHP → JSON.
  - Columnas: id, username, resultado, ip_address, user_agent, created_at.

  CHIPS DE ESTADÍSTICAS (parte superior)

  - Exitosos (resultado = 'exitoso').
  - Fallidos (resultado = 'fallido').
  - Bloqueados (resultado = 'bloqueado').
  - Inactivos (resultado = 'inactivo').
  - Conteos calculados en JavaScript desde los datos embebidos.

  TABLA FILTRABLE
  - Columnas: fecha/hora, usuario, resultado (badge coloreado), IP, User-Agent.
  - Filtro por resultado: dropdown (Todos / Exitoso / Fallido / Bloqueado).
  - Filtro por texto: busca en username o ip_address simultáneamente.
  - Filtrado 100% en cliente (JavaScript) sobre los 200 registros pre-cargados.
  - Badges de color: verde=exitoso, rojo=fallido/bloqueado, naranja=inactivo.

3.4  MÓDULO USUARIOS — admin/pages/usuarios.php
────────────────────────────────────────────────────────────────────────────────
Archivo: /admin/pages/usuarios.php

Gestión de cuentas de administrador del sistema.

  TABLA DE USUARIOS
  - Columnas: avatar, nombre completo, username, estado (Activo/Inactivo), acciones.
  - Botones por fila: Editar info, Resetear contraseña, Activar/Desactivar.
  - Indicador visual de estado: badge verde (activo) o rojo (inactivo).
  - Botón "Nuevo Usuario" en la parte superior derecha.

  MODAL CREAR/EDITAR USUARIO
  - Campos: primer_nombre, segundo_nombre, apellido_paterno, apellido_materno,
    email_contacto, telefono.
  - En modo creación: también pide username y password (mínimo 8 chars).
  - Username validado con regex ^[a-zA-Z0-9_]{3,30}$ (solo alfanumérico+guión bajo).
  - Verificación de unicidad de username en el servidor.
  - POST a admin/api/usuarios.php action=create o action=update.

  MODAL RESET DE CONTRASEÑA
  - Solo pide nueva contraseña + confirmación (sin pedir la contraseña actual).
  - Disponible para administradores con permisos suficientes.
  - POST a admin/api/usuarios.php action=reset_password.
  - Efecto: cierra TODAS las sesiones del usuario afectado.

  ACTIVAR / DESACTIVAR
  - Toggle del campo 'activo' en la tabla usuarios.
  - Al desactivar: también DELETE FROM sesiones WHERE user_id=? (cierre forzado).
  - POST a admin/api/usuarios.php action=toggle_activo.

  CARGA INICIAL
  - GET a admin/api/usuarios.php action=list en DOMContentLoaded.
  - Renderiza tabla dinámicamente con los datos recibidos.

3.5  MÓDULO IMÁGENES — admin/pages/imagenes.php
────────────────────────────────────────────────────────────────────────────────
Archivo: /admin/pages/imagenes.php

Gestor de archivos de imágenes del sistema.

  PESTAÑAS DE CARPETAS (3 tabs)
  - General:   /admin/assets/images/general/    → imágenes de contenido general.
  - Partners:  /admin/assets/images/partners/   → logos de marcas asociadas.
  - Avatares:  /admin/assets/avatars/           → fotos de perfil de usuarios.

  CARGA DE IMÁGENES
  - GET a admin/api/imagenes.php action=list (sin parámetros, devuelve las 3 carpetas).
  - Cada imagen: nombre de archivo, ruta relativa, tamaño en bytes.
  - Se renderiza un grid de tarjetas con vista previa (<img src=...>).

  SUBIDA DE ARCHIVOS
  - Botón "Subir Imágenes" → input type=file multiple.
  - Zona de drag-and-drop: detecta dragover/drop, aplica clase visual de resaltado.
  - Soporta múltiples archivos simultáneos.
  - Barra de progreso por archivo (XHR con evento 'progress').
  - POST a admin/api/contenido.php con FormData (campo 'imagen' + campo 'carpeta').
  - Carpeta destino determinada por la pestaña activa.
  - Al completar → recarga la galería del tab actual.

  ELIMINACIÓN
  - Botón rojo (X) aparece al hacer hover sobre cada tarjeta.
  - Confirma con dialog nativo del navegador.
  - POST a admin/api/imagenes.php action=delete con campo 'path'.
  - Servidor valida que la ruta sea segura antes de eliminar (ver API).
  - Al completar → elimina la tarjeta del DOM sin recargar.

  FORMATOS SOPORTADOS (validación en servidor)
  - JPEG, PNG, WebP, GIF.
  - Tamaño máximo: 5 MB por archivo.

4.1  API DE PERFIL — admin/api/profile.php
────────────────────────────────────────────────────────────────────────────────
Archivo: /admin/api/profile.php

Gestión del perfil del usuario autenticado actualmente.
Requiere Auth::check() en todos los métodos. CSRF obligatorio en POST.

  GET action=get
  - SELECT id, username, nombre, primer_nombre, segundo_nombre, apellido_paterno,
    apellido_materno, email_contacto, telefono, foto FROM usuarios WHERE id=?
  - Graceful fallback por 3 niveles si columnas nuevas no migradas aún.
  - Retorna { ok: true, data: { ...perfil } }

  POST action=update_info
  - Campos: primer_nombre (req), segundo_nombre (opt), apellido_paterno (req),
    apellido_materno (req), email_contacto (req, validado), telefono (req).
  - Construye campo 'nombre' concatenando las partes no vacías.
  - UPDATE usuarios SET nombre=?, primer_nombre=?, ... WHERE id=?
  - Fallback: si columnas no migradas → UPDATE solo el campo 'nombre'.
  - Retorna { ok: true, msg: '...', nombre: 'Nombre completo' }

  POST action=upload_avatar
  - Valida MIME con mime_content_type() (JPG/PNG/WebP/GIF).
  - Tamaño máximo: 2 MB.
  - Nombre de archivo: avatar_{userId}_{timestamp}.{ext}
  - Directorio: /admin/assets/avatars/
  - Elimina avatar anterior del filesystem si existe.
  - UPDATE usuarios SET foto = 'assets/avatars/...' WHERE id=?
  - Retorna { ok: true, path: 'assets/avatars/...' }

  POST action=change_password
  - Valida: todos los campos requeridos, confirmación coincide, mínimo 8 chars.
  - password_verify(current_password, hash_almacenado).
  - Si correcta → password_hash(new_password, BCRYPT, cost=12).
  - UPDATE usuarios SET password_hash=? WHERE id=?
  - Auth::invalidarOtrasSesiones($userId) → cierra sesiones en otros dispositivos.
  - Retorna { ok: true, msg: 'Contraseña cambiada correctamente' }


────────────────────────────────────────────────────────────────────────────────
4.2  API DE USUARIOS — admin/api/usuarios.php
────────────────────────────────────────────────────────────────────────────────
Archivo: /admin/api/usuarios.php

CRUD completo de cuentas de administrador.
Requiere Auth::require(). CSRF en POST.

  GET action=list
  - SELECT id, username, nombre, email_contacto, telefono, activo, foto,
    intentos_fallidos, ultimo_fallo FROM usuarios ORDER BY id
  - Retorna { ok: true, data: [ ...usuarios ] }

  POST action=create
  - Valida username con regex ^[a-zA-Z0-9_]{3,30}$.
  - Valida password >= 8 caracteres.
  - Verifica unicidad: SELECT COUNT(*) WHERE username = ?
  - Si único → INSERT INTO usuarios (username, password_hash, nombre, activo)
    con bcrypt cost 12.
  - Retorna { ok: true, id: nuevoId }

  POST action=update
  - Campos: nombre, email_contacto, telefono (todos opcionales/editables).
  - UPDATE usuarios SET nombre=?, email_contacto=?, telefono=? WHERE id=?

  POST action=toggle_activo
  - Requiere campo 'id' en POST.
  - Lee estado actual: SELECT activo FROM usuarios WHERE id=?
  - Invierte: UPDATE usuarios SET activo = 1-activo WHERE id=?
  - Si se desactiva (nuevo activo=0) → DELETE FROM sesiones WHERE user_id=?
    (forzar logout del usuario desactivado).

  POST action=reset_password
  - Requiere campo 'id' y 'password' en POST.
  - password >= 8 caracteres.
  - password_hash(password, BCRYPT, cost=12).
  - UPDATE usuarios SET password_hash=?, intentos_fallidos=0, ultimo_fallo=NULL
    WHERE id=?
  - DELETE FROM sesiones WHERE user_id=? (cierra todas sus sesiones).

4.3  API DE CONTENIDO (ADMIN) — admin/api/contenido.php
────────────────────────────────────────────────────────────────────────────────
Archivo: /admin/api/contenido.php

API privada de lectura/escritura de contenido + subida de imágenes.
Requiere Auth::check(). CSRF en POST.

  GET ?clave=NOMBRE
  - Llama Contenido::get($clave). Retorna valor JSON de esa clave.
  - Si no se pasa clave → Contenido::getAll(). Retorna todas las claves.

  POST con archivo (multipart/form-data)
  - Detecta si $_FILES['imagen'] existe.
  - Valida MIME: JPG/PNG/WebP/GIF. Tamaño máx 5 MB.
  - Carpeta destino: según campo 'carpeta' del POST:
      'partners' → /admin/assets/images/partners/
      otro       → /admin/assets/images/general/

  - move_uploaded_file() → guarda el archivo.
  - Retorna { ok: true, path: '/admin/assets/images/...' }

  POST con JSON body (Content-Type: application/json)
  - Lee php://input, json_decode().
  - Requiere campos: clave (string) y valor (cualquier tipo JSON).
  - Contenido::set($clave, $valor) → upsert en DB.
  - Retorna { ok: true }

4.4  API DE IMÁGENES — admin/api/imagenes.php
────────────────────────────────────────────────────────────────────────────────
Archivo: /admin/api/imagenes.php

Gestión del sistema de archivos de imágenes.
Requiere Auth::check(). CSRF en POST (delete).

  GET action=list
  - Escanea 3 directorios con scandir():
      /admin/assets/images/general/
      /admin/assets/images/partners/
      /admin/assets/avatars/
  - Filtra entradas '.' y '..' y archivos sin extensión de imagen.
  - Por cada imagen devuelve: nombre, path (relativo), size (bytes).
  - Retorna { ok: true, data: { general: [...], partners: [...], avatares: [...] } }

  POST action=delete
  - Recibe campo 'path' (ruta relativa desde /admin/).
  - Construye ruta absoluta y aplica realpath().
  - Verificaciones de seguridad:
    1. La ruta resuelta DEBE comenzar con el PROJECT_ROOT (evita path traversal).
    2. La ruta DEBE estar dentro de una de las 3 carpetas permitidas.
    3. La extensión DEBE ser jpg, jpeg, png, webp o gif (case insensitive).
  - Si pasa todas las verificaciones → unlink($absolutePath).
  - Retorna { ok: true } o error HTTP 403/400.

PARTE 7 — FLUJOS COMPLETOS DE USUARIO
════════════════════════════════════════════════════════════════════════════════

  FLUJO 1: PRIMER LOGIN DE UN USUARIO NUEVO
  1. Admin navega a /pages/corporativo/login.php
  2. Ingresa credenciales → POST → Auth::login().
  3. Login exitoso → cookie 'dematiq_session' establecida.
  4. Auth::require() detecta isProfileComplete() = false.
  5. Redirect a /admin/complete-profile.php.
  6. Admin llena formulario con nombre completo, email, teléfono y foto.
  7. POST a admin/api/profile.php action=update_info (+ upload_avatar opcional).
  8. Si ok → redirect a /admin/dashboard.php.

  FLUJO 2: PUBLICAR NUEVO CONTENIDO
  1. Admin está en /admin/pages/inicio.php (o cualquier módulo de contenido).
  2. Edita campos, sube imágenes si es necesario.
  3. Hace click en "Guardar".
  4. JavaScript llama CM.set(clave, valor) con X-CSRF-Token automático.
  5. admin/api/contenido.php valida auth + CSRF.
  6. Contenido::set() hace upsert en tabla 'contenido'.
  7. Respuesta ok → JavaScript emite en BroadcastChannel('dematiq-live').
  8. index.html (abierto en otra pestaña/ventana) recibe el evento.
  9. index.html hace fetch('/api/contenido.php?clave=...') y actualiza el DOM.

  FLUJO 3: CAMBIO DE CONTRASEÑA CON CIERRE DE SESIONES
  1. Usuario abre modal de perfil → pestaña Seguridad.
  2. Ingresa contraseña actual + nueva + confirmación.
  3. POST a admin/api/profile.php action=change_password con CSRF.
  4. Servidor verifica contraseña actual con password_verify().
  5. Genera nuevo hash bcrypt (cost 12).
  6. UPDATE usuarios SET password_hash = ? WHERE id = ?
  7. DELETE FROM sesiones WHERE user_id = ? AND token != current_token.
  8. Respuesta ok → modal muestra mensaje de éxito.
  9. Otros dispositivos/pestañas del mismo usuario pierden sesión al siguiente request.

  FLUJO 4: BLOQUEO POR INTENTOS FALLIDOS
  1. Atacante intenta login con username válido pero contraseña incorrecta.
  2. Cada intento → intentos_fallidos++ y ultimo_fallo = NOW().
  3. Al llegar a MAX_INTENTOS=5 → cuenta bloqueada.
  4. Durante 15 minutos → Auth::login() rechaza inmediatamente sin verificar password.
  5. Paralelo: si la misma IP acumula 20 fallos en 15 min → bloqueo por IP
     (independiente del username objetivo).
